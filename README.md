# Git Practice: Continuous Integration

**Author:** Vent1Zzz

## Article

[Continuous Integration](https://martinfowler.com/articles/continuousIntegration.html) by Martin Fowler

## What I Find Interesting

I find the article's emphasis on frequent integration interesting because it connects everyday Git habits to a larger software engineering problem. When developers work separately for too long, combining their changes can become difficult and unpredictable. Integrating small changes frequently makes problems easier to locate and discuss. This gives the commands in this assignment a practical purpose: pulling, committing, and pushing help a team keep a shared understanding of its project.

Another point that stands out to me is that a successful merge does not guarantee working software. Automated builds and tests check whether changes actually work together, including problems that Git cannot detect as text conflicts. For a class project, I would want small, clearly described commits and quick checks so that teammates can review changes and respond to failures promptly. This article makes me see version control as part of a feedback process that supports collaboration, rather than simply a place to save files.
